# MasteryOS Resource Governance — Expanded Model

## Goal

The learner should experience learning as an integrated system rather than a sequence of links to other websites.

## Resource classes

Every resource belongs to one of these classes:

- `native-original` — authored for MasteryOS;
- `licensed` — stored/used under verified rights;
- `provider-embedded` — shown through an allowed provider mechanism;
- `reference` — linked or cited but not reproduced;
- `unknown-rights` — not shippable until resolved;
- `rejected` — prohibited or unsuitable.

## Built-in requirement

For a major topic, the target experience is:

`learn inside MasteryOS → practice inside MasteryOS → assess inside MasteryOS → track inside MasteryOS`

External material is used when it adds unique value, but external navigation should not be the default architecture.

## Catalog breadth

Resource research should search beyond popular platforms. Consider:

- university open courseware;
- official documentation;
- standards/specifications;
- open textbooks;
- technical books with suitable rights;
- open-source repositories;
- conference/tutorial material;
- academic papers;
- official provider training;
- credible specialist material;
- difficult-to-find niche resources.

## Selection criteria

Rank resources by:

- correctness;
- pedagogical quality;
- depth;
- relevance to the curriculum node;
- practical usefulness;
- primary-source status;
- freshness for volatile technology;
- accessibility;
- licensing/reuse status.

## Native transformation

When the original source cannot be embedded or reproduced, MasteryOS may create original instructional material that teaches the same underlying concept without copying protected expression. It must preserve source attribution/reference where appropriate.

## Verification

For important technical material:

`discover → source-check → cross-check → version-check → rights-check → map to curriculum → publish/associate`

## Frontier sources

Rare or advanced material can be included even when there is no polished course. In those cases MasteryOS may assemble an original learning path from papers, specifications, source code, lecture notes, documentation, and carefully verified explanations.

Frontier content must display evidence/uncertainty metadata and should not be presented as settled fact when the underlying field is still evolving.

## Copyright boundary

Do not scrape entire third-party catalogs or copy textbooks/courses/videos into the project merely because they are accessible online. Accessibility is not ownership or reuse permission.

## Resource-to-learning contract

A resource is useful only when attached to a curriculum outcome and assessment path. A 40-hour course with no mapped competencies is not automatically better than a 60-minute authoritative tutorial that teaches the exact required concept.
